## A 类 · 可证明的缺陷

### A1. 平仓取价方向反了

**位置**：7394-7399（`markPrice`）、7758（`stepFastTrade`）、7471（`makeFastTrade`）

**现象**：`markPrice` 本身写对了，但调用语境用反。平掉多头应成交在 bid，代码取了 ask；平掉空头应成交在 ask，代码取了 bid。同时开仓根本不走 `markPrice`——全文仅两处调用（7758、7944），都在平仓侧；开仓价是 `entry = bar.c`，即 feed 的 `last_price`，单边、不含点差。

```js
7396   if (dir > 0 && ticker.ask != null) return ticker.ask;   // 持多仓 → ask
7758   const px = markPrice(tr.dir, ticker);                   // 这是平仓路径
7771   const exit = kind === 'tp' ? tr.tp : kind === 'sl' ? tr.sl : px;
```

**后果**：止盈提前一个点差触发、止损延后一个点差触发，且按 `tr.tp`/`tr.sl` 精确记账。净偏差 = 1.5 × 点差，发生在 **100% 的交易**上，与输赢无关。点差 0.30 美元时每笔 0.45 美元/盎司，占默认止盈 1.8 的 25%。

**修法**：平仓取 `dir > 0 ? bid : ask`；新增开仓取价函数取 `dir > 0 ? ask : bid`。

### A2. 订单块「未回补」判定恒为真

**位置**：5361-5367（`computeSmc`）

**现象**：多头 OB 是阴线，所以 `ob.bot = min(o, c) = c`。扫描从 `ob.i + 1` 开始，而该根的 `open` 等于上一根的 `close`（即 `ob.bot`），且 `low <= open` 是 OHLC 的定义。

```js
5361   for (let i = ob.i + 1; i < klines.length; i++) {
5362     if (ob.dir > 0 && klines[i].l <= ob.bot) { mit = i; break; }   // 恒成立
5367   if (mit == null) obs.push(ob);
```

**实测**：`open[i] === close[i-1]` 的比例为 412/499（黄金是连续行情，`|open[i]-close[i-1]|` 中位数 0.000、p90 0.020），所以必然触发。真实数据 321 个窗口，**未回补 OB = 0.00**；无跳空合成数据 0.000；人为注入 0.02 美元跳空噪声后恢复到 0.898/窗口。

**后果**：9839 行的订单区块矩形**永不渲染**；8677-8679、8685、8695-8697 的 `inOb` 分支是死代码。不影响信号生成，因为 `smcEventPois`(5124) 用的是 `ev.ob` 而非 `obs`。

**修法**：从突破 K 线之后开始扫，或把回补判据改为实体中点 / 50% 穿透。

### A3. `hkldPickIdx` 读取未收盘 HTF K（真前视）

**位置**：4332-4337（`hkldPickIdx`）、4583-4587、4599-4600、9283（绘制）

**现象**：返回最后一个 `t <= 目标时间` 的 HTF 索引，即「在该 1 分钟时刻仍在走的那根 HTF K」。随后用它的**完整 OHLC 与收盘价**判定，并以 `form=false` 判 `'trigger'`。

```js
4334   let i = src.length - 1;
4335   while (i >= 0 && src[i].t > t) i--;
4336   return i;
```

**后果**：画在 10:01 那根 1 分钟 K 上的「低多」标记，用的是 10:00–10:05 这根 5 分钟 K 的收盘价——**提前 4 分钟**；15m 源提前最多 14 分钟。这是全项目唯一一处真正的未来函数，且标记被真实绘制。`recentTrig`(4631) 同样问题。

**修法**：改成取上一根**已收盘**的 HTF K。

### A4. `forming` 恒真，HKLD 约 865 行永不出票

**位置**：4531（`computeHkldHtf`）、4199-4205（`hkldClosedEnd`）、4446 / 4652 / 4656 / 4677 / 4452

**现象**：`hkldClosedEnd` 只要当前时间距最后一根收盘还差 >200ms 就返回 `length-2`，5 分钟源的最后一根几乎永远未收盘，`trigLast > trigClosed` 恒真。

```js
4531   const forming = (chartClosed >= 0 && chartLast > chartClosed)
                    || (trigClosed >= 33 && trigLast > trigClosed);
4452   const vote = status === 'trigger' ? dir : 0;
```

所有能置 `'trigger'` 的出口全被 `forming` 挡住，`vote` 恒为 0，`core`(4499) 恒为 false。「高空低多」是 8 项主条指标之一，`computeHkld` 及其依赖约 865 行（3854-4724），在正常运行下从不投票。`computeHkldChart` 单周期路径同理，但它只在 5m/15m 都不足 34 根的冷启动阶段才跑。

**修法**：修 `forming` 逻辑；或明确把 HKLD 降级为纯展示层，同时按 A3 隔离前视标记。

### A5. 盈亏公式零成本

**位置**：2866-2869（`simPnl`）、7643-7657（`closeSnapshot`）、8485-8486（手工平仓）、7633-7637（回放）

**现象**：三处全部是纯价差。点差 0 次（应 1 次往返），无手续费字段，无滑点——7633 行即使 `bar.l` 跳空穿越 `tr.sl` 仍按 `tr.sl` 精确成交。`tr.spread` 在 7497 被写进交易对象，但从未进入盈亏公式（只在 7481 用于抬高止损距离）。`fmtFunding` 唯一调用点是 10785 的显示。

```js
2868   return (exit - entry) * dir;
7656   pnl: tr.dir * (price - tr.entry),
```

**后果**：盈亏平衡胜率账面 43.75%，真实 57.8%（点差 0.30）到 72.6%（点差走到闸门上限）。**账面把门槛压低 14-20 个百分点。**

另需注意：`holdSec=180` + `coolSec=20` 意味着每小时最多 18 笔。1 分 ATR=0.5 而目标 1.8 时，绝大多数交易会以 `time` 或 `invalid` 出场（账面各约 0 和 -0.3，真实各约 -0.45 和 -0.75）——账面几乎不亏、真实持续渗血。

**修法**：至少扣一个往返点差；`simStats`(8144) 的胜率与累计盈亏需同步修正口径。

### A6. `body || 1e-9` 使 `pin` 判据恒真

**位置**：6908 / 6912（`computeTrap`）、6535 / 6541（`computeBounce`）

```js
6908   const body = Math.abs(sweepBar.c - sweepBar.o) || 1e-9;
6912   const pin = wick >= body * pinWick;      // 1e-9 * 1.3，任何非零影线都成立
```

**后果**：十字星（`c == o`）时 `pin` 无条件通过。这是**无成交量情况下判「诱」的唯一 K 线形态判据**（6915 的三个替代条件之一），在最需要它的场景里失效。1 分钟黄金十字星极常见。

**修法**：改为「实体小于 x·ATR 时 pin 不成立」。

### A7. RSI 周期写死 14，与用户设置分裂

**位置**：6508（`computeBounce`）、6618（`computePull`）、7522（`fastContext`）

**现象**：`state.rsiN` 可被用户改成 6 / 9 / 14。`chartSlice`(3496)、`judge`(8748)、`computeHkldChart`(3886) 跟随设置，上述三处写死 14。

**实测**：同一 180 根序列，最后一根 RSI14=55.20 / RSI9=61.71 / RSI6=71.89；全程最大偏差 |RSI14-RSI6|=16.90。按 `rsiVote`(8610) 的 30/40/60/70 分档，**160 根有效样本中 68 根（42.5%）落在不同投票档位**。

**后果**：用户切到 RSI6 后，副图与「RSI」因子显示 RSI6，而回踩/反弹信号和 10 秒快打面板内部仍按 RSI14 的门槛过滤。同一屏上两块结论矛盾，界面无任何提示。

**修法**：统一读 `state.rsiN`。

**附带**：`rsiSeries`(6393/6398) 在 `ag` 与 `al` 同时为 0（近 n 根无波动）时返回 100 而非中性 50。10 秒周期由 tick 合成 K 线时可能触发，会被 `rsiVote`(8615) 判为「已进超买带」。

### A8. `macdOf` 缺预热屏蔽

**位置**：3662-3672（`macdOf`）、3583-3593（`ema`）、3514-3516（`chartSlice` 绘图）

**现象**：`ema` 用**首值**而非前 n 根 SMA 做种子。末端影响可忽略（180 根时 EMA26 种子权重 9.5e-7），但 MACD 有二次传播：`dif[0] = e12[0] - e26[0] = 0`（两条 EMA 同种子），DEA 又以这个 0 为种子。而 `macdOf` 只有 `if (n < 26) return empty` 一道整体闸门，没有逐根预热 null，180 个值全部非 null 被送去绘图。

**实测**（180 根合成金价序列，典型 |DIF|=0.2888）：

| index | DIF(首值种子) | DIF(SMA种子) | 相对误差 |
| --- | --- | --- | --- |
| 25 | 0.5594 | 0.6917 | **45.8%** |
| 40 | 0.3228 | 0.3626 | 13.8% |
| 60 | 0.3155 | 0.3239 | 2.9% |
| 179 | -0.1591 | -0.1591 | 0% |

**后果**：图表左侧约 40-60 根的 DIF/DEA/柱不可信。对最新一根的判断无影响。

**修法**：仿 `bollCore`(3638) 对 `i < 33` 返回 null。可选：`ema` 改用前 n 根 SMA 做种子。

### A9. 三处缓存键不一致

**位置**：5415（`getSmc`）、3837（`getBollMacd`）、5076（`getStack`）、6374（`getFib`，正确）、5665（`getHs`，正确）、6069（`getSr`，正确）

两类问题：

1. **`getSmc` 缺 `state.tf`**，而 `computeSmc`(5390) 依赖 `smcSigLook(state.tf)`。所有周期 `limit` 均为 180，在一个 5m K 线的第一分钟内，1m 与 5m 的最后一根 `t` / `o` / `h` / `l` / `c` 完全相同 → 键碰撞 → 切换周期后返回上一周期的缓存包。`getHs` / `getSr` 都带了 tf，只有它漏了。

2. **`getBollMacd` 与 `getStack` 的键只含 `t` 和 `c`**，但 `analyzeBoll`(3723-3724) 读取 `h` / `l`：

```js
3723   if (klines[i].h >= upK[i] && klines[i].c <= upK[i]) touchUp = true;
```

影线延伸而收盘价未变时（长影线形成过程中很常见），缓存不失效，`touchUp` / `touchDn` / `touchKind` 停留在旧值。对照 `getFib`(6374) 已正确包含 `h` / `l`。

**修法**：统一键的构成——`[length, t, o, h, l, c, tf, 相关参数]`。

### A10. 点差闸门含死代码，盘口缺失时保护静默失效

**位置**：7502-7506（`spreadTooWide`）、7388-7392（`spreadOf`）、12078-12079（测试注入）

```js
7503   if (spread == null || !(spread > 0)) return false;          // 缺盘口 → 放行
7505   return spread >= 0.28 * tpDist || tpDist < 3 * spread;      // 第二条件是死代码
```

两个问题：

1. 第二条件 `tpDist < 3*spread` 等价于 `spread > 0.333*tpDist`，比第一条件宽，永远不会单独生效。
2. `spreadOf` 在 `ask` 或 `bid` 为 null 时返回 null，`spreadTooWide(null, ...)` 返回 false 放行，且 7481 的 `slDist = max(slDist, 4*spread)` 被跳过。**盘口数据缺失时所有点差保护同时消失，UI 无任何提示。**12078-12079 的测试注入接口直接令 `bid = ask = last`，点差恒为 0。

**阈值本身也过宽**：黄金常态 tpDist 恒为 1.8（被 A11 的钳位固定），允许点差达 0.504 美元/盎司，约等于 1 分 ATR 的 100%——点差比一整根 1 分钟 K 的真实波幅还大，仍然放行。往返真实成本占止盈 42%。

**修法**：删除死条件；点差不可得时拒绝开单而非放行；阈值压到 `0.05~0.08 × tpDist`，或改用 `点差 <= 0.25 × 1分ATR`。

### B2. 消除同源因子重复计票

**位置**：8779-8956（现有 18 条去重边）、7330-7348（`mtfLean`）、8572（`emaVote`）

**已确认的重复**：

**注意**：`hkld` 的去重边缺失当前因 A4 的 vote≡0 未爆发。**修完 A4 后会立刻多出一条重复票**，两者需一起处理。

### B4. 头肩形态：下线还是重构

**位置**：5423-5661

9 道几何门槛的实测通过率（真实数据 1313 个五枢轴候选）：

阈值本身也远比经典形态学宽松：`tSym <= 0.62` 允许两侧时间比 **4.26 倍**；`sym >= 0.48` 允许矮肩只有高肩的 48%；头只需高于肩 **12%**。「头肩顶必须出现在上升趋势之后」这个前提由 `hsPriorMove` 承担，实测通过率 100.0%，从未拒绝过任何候选。

`computeSmc` **零处调用 `atr`**：BOS 无突破幅度门槛，OB 无实体/波幅门槛，FVG 只有 `0.00008 × 价格` 的固定门槛（价格百分比而非 ATR 比例）。

**实测**：每 180 根出现 **13.5 个 BOS/CHoCH**，中位间隔 11 根、p10 间隔 6 根，其中 CHoCH 占 43%。FVG 每 180 根通过门槛 25.7 个、未回补 6.8 个，缺口高度 p10/p50/p90 = **0.24 / 0.54 / 1.45 ATR**——多数只是普通三根阶梯，不是失衡。几乎 100% 的结构事件都会产出一个订单块。

黄金无量是数据源限制（`parseKlines`(3414) 只取 OHLC，接口实测只返回 5 个字段，README 第 144 行的说法准确）。但**无量本可以用的波幅代理一个都没做**：突破 K 线实体 ≥ x·ATR、OB 之后必须紧跟 FVG、BOS 越过前高的幅度 ≥ x·ATR。

**附带**：`k = 2`(5300) 是硬编码常量、不随周期变化，而同一张图上头肩用 3、支压用 4——三种结构定义并存。

**附带**：`smcPoiHold`(5114) 只要求收盘高于区间底部 20% 处、**上方无界**，一根只用影线插进区间顶部、收盘远在区间之上的 K 同样算「守住」。实测 123 个「收盘守住」信号中 **90 个（73.2%）收盘并不在 POI 区间内**，与 5218 的文案「收在区内」不符。

**需要决定**：加多严的位移门槛？事件密度降到什么量级算合理？

### B6. BOLL 轨道在支压面板的定位

**位置**：5778-5832（`srBollCandidates`）、5785-5786、5800-5814、5948-5956

发布说明称此为「参考 Gate 撑压线公开口径」。口径本身无法核实，但代码的**混合方式**有三个矛盾：

1. **画出的价格与统计触碰所用的价格不是同一个东西**。`price` 取最后一根的轨道值（静态快照），而 `touches` 是拿每根 K 线**各自**的轨道值数的。这条「支压位」的触碰历史属于另一条移动的曲线。该 `touches` 随后与摆动点聚类的 `touches` 同权相加，量纲不可比。
2. **BOLL 候选有结构性打分优势**。轨道在趋势里被价格贴着走，`lastI` 天然落在 `n-1` 附近 → `recency` 几乎拿满；同时 `srFindBreak` 从 `lastI + 1` 开始扫，对 BOLL 候选等于从末尾开始扫，**永远返回 null** → 永久保留 `breakI == null ? 1` 的满额加分。摆动点位会被判破位而降到 0.35。实测画出的支压位里 **36% 带 boll20 标记**。
3. **中轨的角色每次穿越就翻转**（5792 `role: last >= lastMid ? 'sup' : 'res'`）。

**实测面板稳定性**：每根新 K 线替换 1.40 条 / 共 7.63 条（**18.4%**）；同一根未收盘 K 的 20 个 tick 内，**65% 的 tick 至少有一条画出的位发生变化**。

**附带**：「角色互换」无任何确认——`lv.role`(5943-5947) 每帧从 `last > lv.price` 重算，价格站到另一侧即刻翻转，不要求破位幅度、不要求回抽、不要求时间确认。0.69 美元的 `thresh` 只用于 `breakI`。

**附带**：`distanceScore` 同时进入 `score`（挑选，权重 2.2）和 `strength`（显示，×8）。**同一条位在价格走近时强度自动升 17 分而历史意义未变**；`score` 与 `strength` 用了两套不一致的触碰:距离比（1.15:2.2 vs 6:8）。UI 的「强/中/弱」(10195) 因此是可靠性与当前相关性的混合体。

**需要决定**：BOLL 轨道保留在支压面板？若保留，必须自成一类，不与静态位共用触碰计数、打分和破位逻辑。

### B7. 带宽分位窗口

**位置**：3709-3710（`percentileRank` 调用）、10693（文案硬编码「近40根」）

窗口固定 40 根。Bollinger 原始 Squeeze 定义是「带宽达近 6 个月最低」（约 125 根日线），常见 BBWP 默认 252 根。1 分钟周期上 40 根只覆盖 40 分钟。

**实测**：200 组带波动率制度切换的合成序列，40 根窗口与 252 根窗口的「挤压」判定（阈值 ≤20%）**只有 79.8% 一致；11.4% 的时刻 40 根报挤压而 252 根不认，8.8% 反之**。

分辨率上，40 个样本的分位只能取 2.5% 的整数倍，且因为用 `<=` 且当前值在样本内，`bwRank` 理论最小值是 2.5%，永远不为 0。

**传导范围最广**：`expandingFromSqueeze`(3714) → `bollVote`(8628) → `bollMacdSignal`(3795) → `stackLayer` 的 `squeeze`(4799) / `wide`(4800) → 套轨的 `open_up`/`open_dn` 分类与核心因子票。

**附带**：`analyzeBoll` 的样本闸门只有 22 根(3685)，样本不足时分位可能只基于 3 个值计算，UI 仍显示「近40根」。

**需要决定**：窗口拉长到多少？还是改用绝对带宽阈值？

### B8. 回放要不要变成真回测

**位置**：7672-7710（`replayFastHistory`）、2370（`FAST_LIMIT`）、7706（`slice(-6)`）

当前不构成回测，六项缺陷按破坏力排序：

1. **样本量小 2-3 个数量级**。窗口恒为 180 根 10 秒棒 = 30 分钟，实际评估 25 分钟；结果再被 `slice(-6)` 砍到 6 笔。n=6 时胜率 95% 置信区间约 ±40 个百分点，**无法区分 44% 与 58%**。要区分 7 个百分点的胜率差需约 400 笔（30-80 小时行情）。主图的 180/360/480 不影响这个窗口。
2. **点差用未来数据**。7680 `const ticker = state.ticker` 把执行瞬间的实时点差施加到 25 分钟前的每一根棒上，用于 `spreadTooWide` 闸门和 7481 的止损抬高。结果依赖「用户何时按刷新」，不可复现。
3. **执行成本为零**（见 A1 / A5）。
4. **同分样本可反复调参**。参数经 `saveSim()`(11750) 落地 localStorage，刷新页面即以新参数重跑同一窗口。`state.fastReplay`(7673) 限制为每会话一次，但「改参数 → 刷新 → 看 6 个结果」的回路完整存在。
5. **删失**。循环结束时仍持仓的 `open` 被静默丢弃；`slice(-6)` 再丢弃早期结果。
6. **实盘/回放信号集不一致**。回放调 `evalFastSetup(..., ticker)` 时 `preview` 为 undefined，启用 1 分钟路径；`updateFastWatch`(7805) 的预览不启用。回放里有一类信号在实时提示中不可见。另外回放循环**不检查交易时段**（实盘 7840 有 `isMarketOpen`）。

**做对的部分应保留**：`barsClosedAsOf`(7350) 对齐严格正确；`hitOnBar`(7633) 歧义棒记止损（保守方向）；入场在 `bars[i].c`、首次出场检查在 `i+1`，无同棒进出；`againstCount`(7660) 只用已收盘数据；**回放结果不写入 `simOrders`**，`simStats`(8144) 不被污染；UI 只画 6 个色块、不宣称胜率。

**需要决定**：是把它明确定位为「最近 25 分钟信号复盘」（当前 UI 已与此相称，只需在文案上讲清），还是投入改造成真回测（需要记录逐棒 bid/ask、扩窗口到 ≥400 笔、区分样本内外、输出置信区间）？

### B9. 建立验证机制

**位置**：`memory/_verify-*.mjs`

当前状态：

- `_verify-judge.mjs` **一条断言都没有**，只采集 DOM 快照、截图、打印 JSON，且无基线比对
- `_verify-hold.mjs` 唯一的实质断言是 `marks.length >= 1` 和「SVG 里有『企稳』二字」，不检查标记的位置、方向、状态
- 全库 grep 无 backtest / 回测 / 样本外 / 参数寻优代码

**这是本清单里其他所有问题的根因**。基础数学层（BOLL 总体标准差、RSI Wilder 平滑、ATR 含跳空 TR、MACD 参数、`chartSlice` 全量算后切片）全部正确，说明能力不是问题；问题是一旦进入自定义规则层，就没有任何机制能发现「头肩在噪声上 82% 命中」或「订单块永不显示」这类缺陷。

**过拟合的量化**：五组形态类指标合计 434 处字面量，剔除指标周期与数值保护后，**真正控制「是否触发 / 是否出票」的可调常数约 290-300 个**，有公认理论出处的只有 13 个（`FIB_RATIOS` / `FIB_EXT` / `FIB_KEYS`），约 4%。`docs/` 与全部代码注释里没有任何标定依据。对照默认 180 根样本，**自由参数是观测数的 1.6 倍**。参数数量 ≥ 样本数时，规则在数学上可以精确复现任意一段历史——因此「它在当前这张图上说得通」不构成证据。

**建议的最小三步**：

1. **数学口径单元测试**。对 `ema` / `bollCore` / `macdOf` / `rsiSeries` / `atr` 用固定输入断言固定输出，与 TradingView 或 TA-Lib 的参考值比对。
2. **随机漫步基准**。对每个形态识别器跑 N 组纯随机漫步，统计命中率。命中率与真实数据无法区分的指标（如当前的头肩）应当下线或重构。这是本次审查用的方法，脚本可复现。
3. **样本外验证**。参数调整前后分别在两段不重叠的历史上评估，而不是在同一段上反复调。

**减轻因素（应保留）**：绝大多数阈值是 ATR 归一化的并配了价格比例地板，能跨波动率状态迁移，比裸价格阈值好得多。但注意 A12 的实测——支压模块的 ATR 项实际从未生效，这个承诺在该模块没有兑现，其他模块需逐一核实。
